# Automatic server world profiles

Updated Et Futurum Plus clients obtain the server's extended-height mode,
imported-Earth mode, and imported surface biome name/ID allocation during the
Forge login handshake. Both endpoints need a build supporting this protocol.
Players no longer need to enable `importedEarthMode`, enable extended height,
or copy `importedbiomes.cfg` to join an imported Earth server.

The **server still requires** its conversion template's configuration:

```cfg
"map compatibility mode" {
    B:importedEarthMode=true
    B:mapCompatibilityMode=false
}
```

This is `config/etfuturum/mapcompat.cfg`. Keep the server's
`config/etfuturum/importedbiomes.cfg` allocation consistent with the converted
world. These files are generated by the mod. An existing converted world's
biome IDs must never be reassigned. Restart the server after configuration
changes. Client Earth settings still select the profile of local singleplayer
worlds; remote servers cannot change those settings or write config files.

## Implementation

* Clients load the height/packet capabilities at startup, including when local
  Earth mode is off. Runtime world bounds and packet widths select the server
  profile. Dedicated servers retain startup selection of their engine patches.
* A bounded, versioned extension to Forge ServerHello supplies the profile;
  ClientHello acknowledges the exact profile before Forge finishes login or
  sends JoinGame/chunks. Invalid/unsupported profiles and incompatible clients
  are rejected before entering the world. No extension selects legacy format;
  old extended-height servers require an update on the server too.
* The profile is separate from local configuration and integrated-server state.
  An Earth server uses 24-bit section masks and 16-bit packet Y coordinates;
  legacy servers keep the original 16-bit masks and 8-bit Y coordinates.
  Non-Overworld world bounds stay provider-defined.
* Imported surface biome objects are scoped to the connection and constructed
  without registering in the global biome array. Client Overworld chunk biome
  lookup interprets the server's numeric IDs through that map. A conflicting
  local biome ID therefore does not overwrite the client registry. Mods that
  bypass world/chunk lookup and access the global biome array directly do not
  receive this connection-specific mapping.
* Starting another handshake and unloading a world clear the profile. Dimension
  changes retain it. Modern water remains a client preference; resource textures
  refresh on the game thread when an Earth connection changes that preference's
  effective value. A disconnect restores ordinary textures.

This does not synchronize every mod configuration or add missing client blocks,
items, rendering mods, or assets. Use matching client/server mod builds. The
server remains responsible for selecting Earth mode and retaining the correct
world biome allocation.

## Verification

`./gradlew --offline build` checks the bounded profile codec (including truncated
and invalid input), packet primitive widths, and production client-hook mappings.
`python3 scripts/run_earth_import_tests.py` runs real Forge hello/ack and rejection,
packet round trips in both formats, temporary biome registry isolation, client-side
world bounds, Earth save/restart, and the existing content/runtime checks.
`python3 scripts/run_earth_import_tests.py --profile legacy` checks legacy mode.

`python3 scripts/run_profile_network_tests.py` opens a disposable development
client and localhost-only Earth/legacy servers on ports 25578/25579. With client
Earth mode off, it joins Earth, then legacy, then Earth again without restarting,
checks upper-world chunk data, renderer-cache access, server biome lookup and
unchanged client settings, then shuts down the fixtures. It requires a GUI and
the already-accepted development EULA at `run/server/eula.txt`. All configs,
worlds, logs and stop files are under `build/profile-network-tests/`.

Production Crucible and optional Angelica/Celeritas integrations still need a
smoke test with the actual pack before replacing a live server installation.
