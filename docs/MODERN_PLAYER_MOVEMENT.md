# Modern player movement

EFR Plus owns sprint swimming, crawling and low-clearance crouching on Forge 1.7.10. The reference target is Minecraft Java 1.21.11. The movement feature is opt-in for this candidate.

## Server settings

Set these under `"backported features"` in `config/etfuturum/mixins.cfg` and restart the server. For a local world, restart the game.

| Setting | Default | Behavior |
| --- | --- | --- |
| `modernPlayerMovement` | `false` | Enables the 1.5-block crouch, 0.6-block crawl and sprint-swim poses. |
| `legacySneakInModernMovement` | `false` | With movement enabled, keeps the 1.7.10 sneak camera, pick ray and 1.8-block hitbox in open space. Clearance can still force a smaller pose when the player is already under a ceiling. Entering a 1.5-block opening from standing requires the modern sneak mode or an approach in a lower pose. |

A movement-enabled server advertises its mode in EFR login protocol v3. A matching client uses the server's mode for prediction even if its local config differs. Older clients must update before joining a movement-enabled server. Disabling the feature preserves the previous EFR protocol versions and height negotiation. The pose byte uses player DataWatcher slot 29 and vanilla spawn/entity-metadata packets. There is no client pose request. The server resolves poses using its collision, water and sneak/sprint state, and the owning client predicts from its movement input. Positions and movement corrections still follow the existing Forge packet path. Remote actors, including replay actors, read the recorded pose byte. The metadata carries only the pose.

## Collision, aim and bridging

The local camera and pick ray use the same physical eye while crouched or horizontal. The server uses that eye for the player eye getter and the existing dig-distance calculation. The player's normal stance packet and the block-placement validation remain on the existing 1.7.10 path. The movement feature uses a single immediate eye transition with no added camera interpolation. The vanilla sneak input, edge-stop algorithm, and sneak slowdown, including EFR's existing Swift Sneak modifier, still run. Low-clearance crouching slows the local player without generating a shift press or changing the sneak flag. Backlytra retains the glide body, eye and hitbox.

In the Forge loopback fixture, disabled and legacy-sneak clients had a 1.80-block collision box and a settled client eye/pick origin of 1.54 blocks above the floor while holding shift. The server's legacy eye was 1.62. Modern crouch measured 1.50 blocks high and 1.27 at both client pick and server eye. The same flat platform stopped the player at approximately X=1.30 and accepted edge placement in all three modes. The 0.27-block client pick-origin difference changes the angle needed to hit a face. The legacy-sneak fallback preserves the measured 1.7.10 aiming geometry.

## Reproducing the Forge fixture

The opt-in `scripts/movement_tests.gradle` init script compiles the fixture separately from the release JAR. Give `runServer` and each `runClient` separate disposable working directories with `-PmovementGameDir=/absolute/path`. The default loopback port is 25578, override with `-PmovementPort`. Use a flat disposable world, localhost, spawn protection off, and enable the mode in the test server's mixins config. Start `runClient --username=PoseDriver` with `-PmovementFixture=modern`, `legacy` or `disabled` to match the server setting. A second client with `-PmovementFixture=observer` and a distinct username verifies remote pose and hitbox changes. Set the client's music to 0 and master volume to 15% before starting. A `FIXTURE_STOP` marker in the disposable working directory stops that process. Successful runs log `MOVEMENT_FIXTURE_CLIENT PASSED` and, for the observer, `MOVEMENT_FIXTURE_REMOTE PASSED`.

Verified in the dev fixture against a dedicated Forge 10.13.4.1614 server over loopback TCP using Java 8. Coverage includes shift toggling, stopping at a flat edge, a stationary side-face pick and confirmed placement, diagonal corner stopping, a server position correction while still holding shift, upside-down slab clearance, releasing shift under the slab, and a stationary ray into the slab underside, crawl exit from a forced one-block gap, sprint-swim entry and release, contained water between waterlogged slabs, remote hitboxes, Elytra takeoff through landing, and reconnect with the server mode reapplied. Legacy mode intentionally blocks walking from the open into the overhead slab with the legacy hitbox. The 1.7.10 baseline uses the disabled mode on the same world and packet path. A separate X35 client disconnected before joining the movement-enabled server. The 256-height fixture exchanged a legacy-width block-effect packet after the position correction. The old-height and both movement-mode profile round trips were also checked at 256 and 400 world height by `./gradlew --offline check build --no-configuration-cache`.

## Crucible diagnosis and crawl rendering follow-up

The supplied live startup log shows Crucible dev-280 (`667a28e2`) with Java 8 and `etfuturum-3.9.0_X39.jar` under `/home/container/mods`. Both clients advertised X39. The exported server `mixins.cfg` was last written during the recorded startup and contained `modernPlayerMovement=false` and `legacySneakInModernMovement=false`. With the master switch off, the server resolves the vanilla pose and omits the movement mode from the login profile. This accounts for the three disabled controls. Set `modernPlayerMovement=true` and keep `legacySneakInModernMovement=false` for modern crouch, then fully restart the server.

The regression starts the player standing under an open wooden trapdoor, aims at the trapdoor, and closes it with the ordinary player interaction path. It checks the server block metadata and crawl pose, then walks through the low tunnel and checks recovery to standing. The client and server log the actual box height and eye, and the client logs its pick origin. The observer checks the tracked hitboxes and captures the crawl stance.

X40 lowers the third-person crawl model and points its arms forward with a small alternating stroke. The ordinary arm swing is retained when attacking with the right arm, and bow use keeps its vanilla arm angles. The pose applies to the player model and armor that uses its biped animation. This is a client render change. The camera, collision, server poses, and wire protocol are unchanged.

[Modern Combat & Movement 0.1.0.41 for 1.7.10](https://www.curseforge.com/minecraft/mc-mods/modern-combat-movement/files/9678316) has separate crawl and swim render classes and configuration entry points for movement, combat and offhand. Its crawl layer blends in a forward reach and alternating limb motion and counter-rotates the prone head. The beta adds equipment and combat systems, and the release notes describe optional Combatives integration for enhanced third-person animations. Modern Poses has a fuller arm sweep with a blend into swimming or crawling, applied on the biped after vanilla angles so armor can follow. The projects are rendering references. EFR includes no dependency on either mod.

The modern fixture passed on Forge 10.13.4.1614 at 256 and 400 height and on the supplied Crucible dev-280 binary at 400 height with the publisher builds of [ProtocolLib 3.6.5](https://dev.bukkit.org/projects/protocollib/files/910338) and [SuperVanish 6.2.18](https://github.com/LeonMangler/SuperVanish/releases/tag/6.2.18) enabled. Both clients negotiated modern mode and agreed with the server on the 1.50-block crouch and the 0.60-block crawl and swim hitboxes. The server eye and client pick origin were 1.27 blocks above the feet in crouch and 0.40 in crawl and swim. Both servers recorded swimming and sprint release in ordinary water and in the waterlogged passage. The observer registered all four poses and the new forward arm pose. At 256 height, Forge also passed the legacy sneak fallback and reproduced the three reports in disabled mode, even though the trapdoor itself closed.

The first 400-height dedicated Forge development run stopped when animal pathfinding loaded the extended-height `MixinChunkCache`, which targets two lighting methods Forge strips on the dedicated server. The 400-height movement run passed in a fresh flat desert with animals and structures disabled. That terrain setup isolates movement coverage from the separate pathfinding startup failure.

The X40 Wargames Event 2.0.16 HUD fixture on bundled Java 21 confirmed identical transforms for the helmet, crosshair, armor, health, food, hotbar and XP across dry standing, crouching, crawling and release. The submerged crawl added the 10-pixel air row and moved the WGQOL profile strip up accordingly. The local copy excluded Kinetic, ReAuth, Gliby's Voice Chat and Custom Main Menu. Full live plugin settings, mixed X39/X40 clients, and third-person crawl with the pack's custom equipment and shader combinations still need verification.

## Swim stability and first-person item lighting

In X40, the 1.7.10 client cancelled ordinary sprint on horizontal collision. The movement resolver immediately used that flag to stand the player up, even if they were still holding sprint in the water. The Forge fixture dropped swim on 22 of 23 submerged wall-contact ticks. Releasing just sprint in open water also kept swimming while forward remained held.

X41 resolves an active swim after the tick's sprint input and leaves aquatic sprint active during wall contact while in water. Solid blocks still stop movement. If the sprint key is held during a swim, releasing it ends the swim even when forward stays held. A new swim still requires immersion at the entry eye height. The server continues to use the ordinary sprint flag and its own water and collision checks. No new camera interpolation or protocol field is involved.

The first-person hand renderer used the standing position to sample the lightmap, which could point into the solid ceiling during crawl. X41 uses the physical eye position for the lightmap lookup in crawl and swim. Angelica's dynamic light lookup still receives that call.

At 400 height, both dedicated Forge and Crucible dev-280 passed the trapdoor, bridge, slab and waterlogged passage checks, plus shallow wading and the sprint-key release check with forward held. Both ran 23 submerged wall-contact ticks with zero client pose drops, and the servers confirmed the player was still swimming. The lit tunnel test confirmed that the first-person item received the same packed light as the crawl eye, while the ceiling returned zero. The Crucible run included ProtocolLib 3.6.5 and SuperVanish 6.2.18 from the same publisher builds used for X40.

The 256-height Forge run also passed legacy sneak, including edge stop and placement. In the Java 21 pack comparison, X40 passed packed light 0 into the FMUR M4A1 renderer and the item appeared black. X41 passed 224, matching the crawl-space sample, and the gun remained visible. The fixed HUD and air row checks passed again. This pack run had Angelica installed with shaders off. The full live plugin and anticheat configuration remains a separate test.
